책상 위 1m 높이에서 공을 손에서 놓습니다. 0.5초 뒤 공은 어디에 있을까요? 관절각으로 손끝 위치를 구하던 계산으로는 이 질문에 답할 수 없습니다. 공의 질량, 아래로 당기는 중력, 그리고 0.5초라는 시간이 함께 있어야 다음 위치가 나옵니다.

처음 시작한다면 순서대로 읽으세요: MuJoCo 시작하기(설치 확인, 뷰어, 숫자로 보기) → XML 읽는 법과 로봇 부품 표 → 이 글. 내 PC에서 예제를 돌리는 방법은 예제 실행하기입니다.

이 장면에서 고정한 조건

여기서부터는 자세 한 장을 계산하는 대신, 힘을 받은 물체가 시간이 지나며 어떻게 움직이는지를 계산합니다. MuJoCo는 그 계산을 대신 해 주는 컴퓨터 속 실험실입니다. 이번 차시는 공 하나, 진자 하나로 끝까지 갑니다. 고정하는 것은 장면입니다. 질량·모양·중력·시간 간격을 한 번 정하고, 바꾸는 것은 시간뿐입니다.

사진 한 장에서 동영상으로

파란 실험판 A만 한 걸음 움직입니다

  1. 왼쪽 초록 MjModel은 질량·중력·시간 간격 설정입니다. 오른쪽 파란 A·살구색 B는 각각의 시간·위치·속도 MjData입니다. 두 화살표는 같은 설정을 참조한다는 뜻입니다.
  2. 중력과 Δt=0.002s를 고정하고 mj_step(model,A)만 한 번 부르면 A.time=0.002, B.time=0입니다. 공의 움직임은 A에만 반영됩니다.
  3. 모델의 중력을 −9.81→−1.62m/s²로 바꾸면 이후 A·B 계산 모두 달라집니다. 상태는 둘이어도 규칙은 하나를 공유하기 때문입니다. mj_resetData(model,A)는 A의 상태를 되돌리고 중력 설정은 유지합니다.

순기구학은 “이 자세일 때 손이 어디 있나”라는 사진 한 장을 계산했습니다. 물리 시뮬레이션은 “이 힘을 받으면 다음 순간 어디 있나”를 계산해 사진을 이어 붙입니다. 그래서 할 일의 순서가 정해져 있습니다.

MJCF: 무엇을 놓을까?→Model: 실험 규칙+Data: 지금 상태→step: 다음 순간

이 화살표는 공간 이동이 아니라 계산 순서입니다. 같은 공·중력·Δt를 정한 Model을 두고, Data의 시간·위치만 step마다 바꿉니다. Δt=0.002초이면 100걸음이0.2초입니다. 이 과정 뒤의 화면 회전은 계산한 공 위치를 바꾸지 않습니다.

첫 단계는 장면을 글로 적는 일입니다. 무엇이 바닥이고, 무엇이 움직이며, 어디에 경첩이 있고, 중력은 어느 쪽으로 얼마나 강한지를 XML로 적습니다. 두 번째 단계에서 그 글을 계산용 모델로 바꾸고, 세 번째 단계에서 현재 상태를 따로 만듭니다. 마지막으로 0.002초짜리 걸음을 반복해 시간을 진행합니다.

위치를 안다고 다음 순간을 아는 것은 아닙니다

손끝 좌표가 (0.3, 0.2)라는 사실은 지금 어디 있는지만 말해 줍니다. 다음 순간의 위치는 질량, 힘, 중력, 현재 속도, 시간 간격이 함께 정합니다. 이번 차시의 계산이 기구학과 갈라지는 지점입니다.

이 차시에는 공과 진자로 이 흐름을 익히고, 낙하와 마찰처럼 답을 아는 문제로 계산이 맞는지 채점합니다. 화면에 예쁘게 보인다는 것과 물리 계산이 정확하다는 것은 다른 이야기입니다. 그래서 마지막에는 손으로 푼 값과 시뮬레이터의 값을 나란히 놓고 비교합니다.

문 한 짝으로 읽는 MJCF 태그

MuJoCo의 XML(MJCF)에는 태그가 많지만, 문 한 짝에는 여덟 개면 충분합니다. option default body joint geom site actuator sensor. 그림 세 장으로 큰 모양을 잡고, 태그마다 속성 하나만 바꿔 숫자가 어떻게 달라지는지 봅니다.

경첩부터 보세요

  1. 먼저 동그란 경첩을 찾습니다. 경첩은 제자리에 있고 문 전체가 그 둘레를 돕니다.
  2. 회색 문이 파란 문으로 바뀝니다. 손잡이(주황 점)가 점선 원을 따라 위로 올라갑니다. 문과 손잡이는 한 덩어리라서 같은 각도 θ만큼 같이 돕니다.
  3. 양의 θ는 x축에서 y축 쪽으로, 즉 위에서 볼 때 반시계 방향입니다. 막대(z축)가 화면 밖으로 나오기 때문입니다.

들여쓰기 하나가 소속 하나입니다

  1. 왼쪽 mujoco에서 오른쪽으로 갈수록 작은 부품입니다. 문(body)은 worldbody 안에 있고, 경첩(joint), 문짝 모양(geom), 손잡이 표시(site)는 문 안에 있습니다.
  2. 주황 점선을 따라가 보세요. motor와 jointpos는 문 안이 아니라 따로 있지만, 이름 "hinge"로 경첩을 가리킵니다. 이름이 연결선입니다.
  3. option, default, actuator, sensor는 문을 만드는 부품이 아닙니다. 계산 규칙, 공통값, 입력, 측정을 따로 모아 둔 목록입니다.

① 문 파일 전체: 열다섯 줄이 문 한 짝입니다

위 나무 그림을 글로 쓰면 아래 XML입니다. 들여쓰기가 소속이고, name="hinge"가 motor와 sensor가 경첩을 찾는 연결선입니다.

<mujoco model="door">
  <option timestep="0.002"/>
  <default>
    <geom rgba="0.2 0.5 0.7 1"/>
  </default>
  <worldbody>
    <body name="door" pos="0 0 1">
      <joint name="hinge" type="hinge" axis="0 0 1"/>
      <geom type="box" pos="0.4 0 0" size="0.4 0.02 0.5"/>
      <site name="handle" pos="0.75 0 0" size="0.03" rgba="1 0.4 0 1"/>
    </body>
  </worldbody>
  <actuator><motor name="opener" joint="hinge"/></actuator>
  <sensor><jointpos name="angle" joint="hinge"/></sensor>
</mujoco>

② 돌려서 숫자 하나 얻기

XML을 door.xml로 저장하고 아래 함수로 돌립니다(실행 방법은 예제 실행하기).

import mujoco

def run(xml, steps=100, ctrl=1.0):
    model = mujoco.MjModel.from_xml_string(xml)
    data = mujoco.MjData(model)
    if model.nu:
        data.ctrl[0] = ctrl
    for _ in range(steps):
        mujoco.mj_step(model, data)
    mujoco.mj_forward(model, data)
    return model, data

xml = open("door.xml").read()
model, data = run(xml)
print(data.time, data.sensor("angle").data[0])

결과: 100걸음 뒤 시간 0.2초, 각도 0.0030 rad(0.17°). 입력 1은 목표 각도가 아니라 회전력 1 N·m이고, 문이 무거워서(32 kg) 0.2초 동안은 조금밖에 돌지 않습니다.

마지막 mj_forward는 위치(xpos)와 센서값을 최신으로 맞춥니다. 아래 실험은 모두 이 run을 쓰고 xml.replace("바꿀 부분", "새 부분")으로 한 군데만 고칩니다.

③ 여덟 태그, 속성 하나씩 바꾸면 무엇이 달라지나

태그마다 한 줄만 고쳐 같은 run을 돌린 결과입니다(모두 MuJoCo 3.17.0 실행값, 기준은 ② 결과 0.00296 rad). 각 줄의 코드와 이유는 아래 접힌 칸에 있습니다.

태그하는 일바꾼 한 줄달라진 숫자
option계산 규칙timestep 0.002 → 0.01같은 100걸음이 0.2초 → 1.0초, 각도 0.0030 → 0.0739 rad
default공통값 물려주기joint damping="2"를 default에dof_damping 0 → 2, 각도 0.00296 → 0.00290 rad
body덩어리와 기준점pos z 1 → 1.5손잡이 z 1.0 → 1.5 (손잡이 줄은 그대로)

④ 더 깊이 (선택): 태그마다 하나씩 해 보기

표의 한 줄마다 코드, 이유, 흔한 실수를 적었습니다. 필요한 태그만 펼치세요.

1. option: 한 걸음에 몇 초를 흘릴까

하는 일 장면 전체의 계산 규칙입니다. 문 파일은 한 걸음의 가상 시간(timestep)만 적었습니다. 이 줄을 지워도 기본값이 같아서 결과는 같지만, 적어 두면 "이 숫자는 이 규칙으로 계산했다"가 파일에 남습니다.

속성뜻단위기본값
timestep한 번 mj_step 할 때 흐르는 시간초0.002
gravity중력 가속도 방향과 크기m/s²0 0 -9.81
하나만 바꿔 보기: timestep 0.002 → 0.01
model, data = run(xml.replace('timestep="0.002"', 'timestep="0.01"'))

같은 100걸음인데 data.time이 0.2초에서 1.0초가 되고, 각도는 0.00296 rad에서 0.0739 rad로 25배가 됩니다. 한 걸음이 5배 길어져 시간이 5배가 되었고, 같은 힘으로 5배 오래 밀면 각도는 시간의 제곱(5×5=25)으로 늘기 때문입니다.

걸음 수가 아니라 시간을 맞춰 비교하려면 0.01초 걸음을 20번만 걸으면 됩니다(run(…, steps=20)). 시간은 똑같이 0.2초인데 각도는 0.00307 rad입니다. 0.002초 걸음의 0.00296 rad보다 약 4% 큽니다. 걸음이 클수록 계산이 거칠어집니다.

걸음 수를 시간으로 착각하지 마세요. 시간은 걸음 수 × timestep이고, data.time으로 확인합니다.

2. default: 공통값을 한 번만 적기

하는 일 여러 요소가 같은 값을 쓸 때 한 번만 적어 둡니다. 문 파일의 <default><geom rgba=…/>는 색을 적지 않은 문짝 geom에 파란색을 물려줍니다. default에 없고 geom에도 없으면 회색(0.5 0.5 0.5 1)이 됩니다.

쓰는 법뜻
<default> 안에 태그 이름과 속성그 종류 요소가 직접 안 쓴 속성의 기본값이 됩니다. 속성 이름은 그 태그의 것과 같습니다.
요소에 직접 쓴 값default보다 항상 우선합니다.
하나만 바꿔 보기: default에 관절 댐핑 넣기
xml2 = xml.replace('<geom rgba="0.2 0.5 0.7 1"/>',
                   '<geom rgba="0.2 0.5 0.7 1"/><joint damping="2"/>')
model, data = run(xml2)
print(model.dof_damping[0])

hinge 줄에는 damping을 쓰지 않았는데 dof_damping이 0에서 2가 되고, 각도는 0.00296 rad에서 0.00290 rad로 조금 줄어듭니다. 댐핑은 속도에 비례해 움직임을 막는 힘이라서, 물려받은 값이 문의 회전을 늦춘 것입니다.

이어서 hinge 줄에 damping="0.5"를 직접 쓰면 dof_damping은 0.5가 되고 각도는 0.00294 rad입니다. 직접 쓴 값이 default를 이깁니다.

default에 색을 적었다고 모든 geom이 그 색이 되는 것은 아닙니다. 문짝에 rgba="1 0 0 1"을 직접 쓰면 model.geom_rgba[0]는 [1, 0, 0, 1]이 되고 default 파랑은 무시됩니다.

3. body: 같이 움직이는 덩어리와 기준점

하는 일 한 덩어리로 움직이는 부품을 묶고 그 부품의 기준점(좌표 원점)을 정합니다. 문 body의 기준점은 경첩 자리입니다. 안에 든 joint, geom, site의 pos는 모두 이 기준점에서 잰 거리입니다. 이 묶음이 없으면 문짝과 손잡이가 같이 도는 한 덩어리가 되지 못합니다.

속성뜻단위기본값
name다른 곳에서 이름으로 찾을 때 쓰는 이름없음생략 가능
pos부모 기준 위치 (worldbody 안이면 세계 좌표)m0 0 0
하나만 바꿔 보기: body pos 0 0 1 → 0 0 1.5
model, data = run(xml.replace('pos="0 0 1"', 'pos="0 0 1.5"'), steps=0)
print(data.site("handle").xpos)

손잡이의 세계 좌표가 (0.75, 0, 1.0)에서 (0.75, 0, 1.5)로 바뀝니다. 손잡이 줄은 한 글자도 안 고쳤는데 같이 올라갑니다. 손잡이의 pos가 문 기준점에서 잰 값이기 때문입니다. pos="2 0 1"로 바꾸면 손잡이는 (2.75, 0, 1.0)이고, 100걸음 뒤 각도는 처음과 같은 0.00296 rad입니다. 문 전체가 평행이동했을 뿐입니다.

geom이나 site의 pos 0.75를 세계 좌표로 읽지 마세요. body를 x=2로 옮기자 손잡이가 0.75가 아니라 2.75에 있습니다.

4. joint: 어떤 움직임을 허용할까

하는 일 body가 부모에 대해 움직일 수 있는 방식을 정합니다. 문의 hinge는 z축 둘레 회전 하나만 허용합니다. joint가 없으면 문은 움직일 자유가 없습니다(모델의 nq가 0).

속성뜻단위기본값
typehinge는 회전, slide는 직선 이동없음hinge
axis회전축 또는 이동 방향 (body 기준)없음0 0 1
range움직일 수 있는 범위 (적으면 한계 적용)hinge는 도, slide는 m0 0 (제한 없음)
namemotor와 sensor가 찾는 이름없음생략 가능
하나만 바꿔 보기: hinge → slide, 방향 1 0 0
x = xml.replace('type="hinge" axis="0 0 1"', 'type="slide" axis="1 0 0"')
model, data = run(x)
print(data.sensor("angle").data[0], data.site("handle").xpos)

같은 센서 "angle"이 이제 0.000631을 읽는데, 단위가 라디안이 아니라 미터입니다. 문은 돌지 않고 x 방향으로 밀려서 손잡이가 0.75에서 0.750631로 갑니다. 손으로 계산해도 힘 1 N, 질량 32 kg이면 ½×(1/32)×0.2² = 0.000625 m로 거의 같습니다. jointpos는 관절 종류에 맞는 값(회전은 rad, 직선은 m)을 읽습니다.

한 가지 더: range로 한계 두기
x = xml.replace('axis="0 0 1"/>',
                'axis="0 0 1" range="0 0.1"/>')
model, data = run(x, steps=500)

500걸음(1초) 뒤 한계가 없으면 0.0733 rad인데, range를 쓰면 0.00175 rad에서 멈춥니다. 한계가 0.1 rad가 아니기 때문입니다. 왜 그런지는 아래 "각도 단위" 메모에 있습니다.

hinge의 range는 기본이 도(degree)입니다. 라디안으로 생각하고 range="0 1.57"이라 쓰면 1.57도가 됩니다.

5. geom: 모양, 충돌, 질량

하는 일 눈에 보이는 모양이자 부딪히는 면이고, 질량의 근거입니다. 문짝 box의 부피 0.8×0.04×1.0 = 0.032 m³에 밀도 1000 kg/m³를 곱하면 32 kg이고, 실제로 model.body("door").mass[0]가 32.0입니다.

속성뜻단위기본값
type모양 종류 (box, sphere …)없음sphere
sizebox는 x, y, z 반길이 셋m0 0 0
posbody 기준점에서 geom 중심까지m0 0 0
density질량을 계산할 때 쓰는 밀도kg/m³1000

중심의 흰 점에서 양쪽으로 보세요

  1. 가운데 흰 점이 pos x=0.4, 즉 geom의 중심입니다. 거기서 왼쪽 끝(경첩)과 오른쪽 끝이 똑같이 0.4 m입니다. 이 0.4가 size입니다.
  2. 그래서 size는 전체 길이의 반입니다. 점선 주황 막대처럼 0.4를 전체 길이로 읽으면 문이 절반 길이로 보입니다.
  3. 손잡이 site는 문 위의 한 점이라서 문이 돌면 같이 돕니다.
하나만 바꿔 보기: size 0.4 → 0.8 (x 반길이)
model, data = run(xml.replace('size="0.4 0.02 0.5"', 'size="0.8 0.02 0.5"'))
print(model.body("door").mass[0], data.sensor("angle").data[0])

질량이 32에서 64 kg으로 두 배가 되고, 100걸음 뒤 각도는 0.00296 rad에서 0.000845 rad(약 0.29배)가 됩니다. 문이 길어지고 무거워져 같은 힘 1 N·m로는 돌리기 어려워졌기 때문입니다. pos는 그대로 0.4이므로 문짝은 x=−0.4에서 1.2 m까지 경첩 뒤쪽으로도 튀어나갑니다.

size를 전체 길이로 읽지 마세요. 문을 0.8 m로 만들려면 반길이 0.4와 중심 0.4가 함께 필요합니다.

6. site: 질량 없는 표시 핀

하는 일 body에 꽂아 두는 표시점입니다. 부딪히지도 않고 질량도 없지만 body와 함께 움직여서 "손잡이가 지금 어디인가"를 물을 수 있고, 센서를 붙이는 자리로도 씁니다.

속성뜻단위기본값
name위치를 읽거나 센서를 붙일 때 쓰는 이름없음생략 가능
posbody 기준점에서의 위치m0 0 0
size표시 구의 크기(반지름)m0.005 0.005 0.005
rgba표시 색없음0.5 0.5 0.5 1
하나만 바꿔 보기: site 줄을 지워 보기
site = '<site name="handle" pos="0.75 0 0" size="0.03" rgba="1 0.4 0 1"/>'
no_site = xml.replace(site, '')
m0, _ = run(no_site)
m1, d1 = run(xml)
print(m0.body("door").mass[0], m1.body("door").mass[0])

질량은 둘 다 32.0 kg이고 geom은 둘 다 1개이며 site만 1개에서 0개가 됩니다. site는 질량 계산에 들어가지 않습니다. 손잡이 위치는 닫혔을 때 (0.75, 0, 1.0)이고, 100걸음 뒤 (0.75, 0.0022, 1.0)입니다. 경첩에서의 거리는 여전히 0.75 m입니다. 돌아도 거리를 지키는 점이 site입니다.

mj_forward를 부르기 전에 data.site("handle").xpos를 읽으면 [0, 0, 0]입니다. 또 model.site_pos는 언제나 body 기준의 [0.75, 0, 0]이고, 세계 좌표는 data.site(…).xpos입니다.

7. actuator: 입력 숫자를 힘으로 바꾸기

하는 일 data.ctrl의 숫자를 관절에 가하는 힘으로 바꿔 줍니다. 문의 motor는 입력에 gear를 곱한 값을 hinge의 회전력으로 씁니다. actuator가 없으면 model.nu가 0이어서 문을 밀 방법이 없습니다.

속성뜻단위기본값
name이 구동기의 이름없음생략 가능
joint힘을 줄 관절의 이름없음필수
gear입력에 곱하는 배율 (첫 숫자)없음1 0 0 0 0 0
ctrlrange입력 범위를 제한입력과 같음0 0 (제한 없음)
하나만 바꿔 보기: gear 1 → 10
x = xml.replace('joint="hinge"/></actuator>',
                'joint="hinge" gear="10"/></actuator>')
model, data = run(x)

입력은 같은 1인데 각도가 0.00296 rad에서 0.0296 rad로 정확히 10배가 됩니다. 입력 1이 10 N·m의 회전력으로 바뀌었기 때문입니다.

입력은 목표 각도가 아니라 힘입니다. ctrlrange="-0.5 0.5"를 쓰고 입력 1을 넣으면 data.ctrl[0]는 1.0 그대로인데 실제 힘은 0.5로 잘려 각도가 0.00148 rad로 줄어듭니다.

8. sensor: 측정값을 배열에 적기

하는 일 시뮬레이션 값을 data.sensordata라는 한 줄 배열에 읽기 쉽게 적어 줍니다. 문의 jointpos는 경첩의 각도를 읽습니다. 센서가 없으면 값은 data.qpos에서 직접 찾아야 합니다.

속성뜻단위기본값
name값을 이름으로 읽을 때 쓰는 이름없음생략 가능
jointjointpos·jointvel이 잴 관절 이름없음필수
objtype, objnameframepos가 잴 대상의 종류(site)와 이름없음필수
하나만 바꿔 보기: 센서 두 개 더 달기
more = '''<sensor><jointpos name="angle" joint="hinge"/>
  <jointvel name="speed" joint="hinge"/>
  <framepos name="handlepos" objtype="site" objname="handle"/></sensor>'''
old = '<sensor><jointpos name="angle" joint="hinge"/></sensor>'
model, data = run(xml.replace(old, more))
print(data.sensordata)

값이 5개 나옵니다: [0.002957, 0.029279, 0.749997, 0.002218, 1.0]. 첫 칸은 각도(rad), 둘째 칸은 각속도(rad/s), 셋째~다섯째 칸은 손잡이의 x, y, z(m)입니다. XML에 적은 순서대로 이어 붙고, 각도와 속도는 1칸, framepos는 3칸을 씁니다. 이름으로 읽으면(data.sensor("speed").data) 순서를 외울 필요가 없습니다.

센서 순서를 바꾸면 sensordata[0]의 뜻이 바뀝니다. jointvel을 앞에 쓰면 [0]은 속도 0.0293이 됩니다. 이름으로 읽으세요.

메모: 이름은 연결선, 각도는 라디안
이름이 틀리면 모델이 안 만들어집니다
bad = xml.replace('joint="hinge"/></actuator>',
                  'joint="hinje"/></actuator>')
run(bad)

motor가 가리킨 이름 hinge를 hinje로 잘못 쓰면 from_xml_string이 멈추고 이렇게 말합니다: unknown transmission target 'hinje' for actuator id = 0 … Element name 'opener', id 0, line 13. jointpos 쪽을 틀리면 unrecognized name 'hinje' of sensorized object … Element name 'angle', id 0, line 14입니다.

파이썬에서 data.sensor("angel")처럼 이름을 틀리면 Invalid name 'angel'. Valid names: ['angle']이 나옵니다. 말해 주는 요소의 이름과 줄 번호를 따라가면 됩니다.

XML의 각도는 도, 계산 결과는 라디안
x = xml.replace('axis="0 0 1"/>', 'axis="0 0 1" range="0 90"/>')
model, data = run(x, steps=0)
print(model.jnt_range[0])

XML에 쓴 range="0 90"은 90도로 읽혀 model.jnt_range에서 [0, 1.5708] rad가 됩니다. 문이 π/2 rad(90도)까지 열렸을 때 jointpos가 읽는 값도 1.5708입니다.

앞 실험의 range="0 0.1"은 0.1도, 곧 0.001745 rad였습니다. 파일을 라디안으로 쓰고 싶으면 <compiler angle="radian"/>를 쓰는데, 그러면 range="0 90"은 [0, 90]으로 읽습니다.

진자: 수평으로 든 추를 놓으면

문 경첩처럼 한 축만 돌 수 있는 관절에 추를 매답니다. 처음에 수평으로 들었다 놓으면 추는 중력 때문에 아래로 내려갔다가 반대편으로 올라갑니다. 컴퓨터에 “그네처럼 흔들려”라고 적을 수는 없으니, 대신 관절·추·중력·처음 각도를 적습니다. 고정하는 값은 경첩 축(y축), 추까지의 거리 0.5m, 마찰 없음, 시간 간격 0.002초입니다.

<mujoco>
  <worldbody>
    <body pos="0 0 1">
      <joint type="hinge" axis="0 1 0"/>
      <geom type="sphere" pos="0 0 -0.5" size="0.05"/>
    </body>
  </worldbody>
</mujoco>
한 줄쉬운 뜻
body pos="0 0 1"관절이 붙은 몸체 기준점을 세계의 높이 1m에 둡니다.
hinge, axis="0 1 0"y축 방향 경첩 하나로만 회전합니다.
sphere pos="0 0 -0.5"몸체 기준점보다 0.5m 아래에 구 중심을 둡니다. 이 상대 위치는 회전하면 함께 돕니다.
size="0.05"구의 반지름은 5cm입니다. 추 중심까지의 0.5m와 다른 값입니다.

이 장면을 읽는 코드는 네 줄이면 충분합니다.

모델 = mujoco.MjModel.from_xml_string(xml)
데이터 = mujoco.MjData(모델)
데이터.qpos[0] = np.deg2rad(90)
for _ in range(100):
    mujoco.mj_step(모델, 데이터)

첫 줄은 글로 적은 장면을 계산용 모델로 바꿉니다. 둘째 줄은 이 실험의 현재 상태를 만듭니다. 셋째 줄은 첫 관절의 초기 각도를 90°로 넣되 라디안으로 변환합니다. 마지막 두 줄은 0.002초짜리 걸음을 100번 진행하므로 총 0.2초입니다. 여기서 출력되는 것은 각도 하나가 아니라, 그 0.2초 뒤의 상태 전체입니다.

교안에서 기록한 값

0.2초 간격으로 읽은 각도는 90.0 → 67.5 → 6.6 → −58.7 → −89.2 → −75.3°입니다. 코드의 100걸음 한 번으로 이 여섯 값이 모두 출력되는 것은 아닙니다. 교안 그림은 더 긴 시간 동안 걸음마다 각도를 기록해 0.2초 간격으로 골라 놓은 것입니다.

마찰이 없는 예제라 추는 반대편에서도 거의 같은 높이까지 올라갑니다. 완전히 같은 값이 아닌 데에는 수치 계산 오차가 섞여 있습니다. 이 값들은 교안 기록이고, MuJoCo 3.17.0으로 다시 실행해 같은 값이 나오는 것을 확인했습니다(MuJoCo 시작하기의 표와 그림).

왜 90을 그대로 qpos에 넣지 않을까?
회전 관절의 qpos 단위는 라디안입니다. 90을 넣으면 90라디안이지 90°가 아닙니다. 90°는 π/2라디안입니다. 각도를 다루는 코드에서 단위를 먼저 확인하는 습관이 여기서 시작됩니다.

무대 대본 쓰기: 바닥과 공이 있는 장면

연극을 준비할 때 무대·배우·조명·규칙을 정하듯, MJCF라는 XML 형식으로 장면을 적습니다. body는 함께 움직이는 몸체, geom은 그 몸체의 모양과 충돌 표면입니다. 한 body에 geom 여러 개를 붙이면 손잡이와 문판처럼 같이 움직이는 복합 모양이 됩니다. 이번 장면은 바닥 위 1m에 공을 두고, 공만 자유롭게 움직이게 합니다.

숫자·공식·코드로 이어 보기
<option timestep="0.002" gravity="0 0 -9.81"/>
<worldbody>
  <light pos="0 0 3" dir="0 0 -1"/>
  <geom name="floor" type="plane" size="2 2 0.1"
        rgba="0.8 0.8 0.8 1"/>
  <body name="ball" pos="0 0 1">
    <freejoint/>
    <geom name="ball_geom" type="sphere" size="0.1"
          rgba="0.9 0.3 0.2 1"/>
  </body>
</worldbody>
  • option: 한 걸음은 0.002초, 중력은 z 아래쪽으로 9.81m/s². 이 두 값이 모든 계산의 기준입니다.
  • worldbody: 움직이지 않는 세계 기준. 바닥처럼 고정된 geom을 바로 붙일 수 있습니다.
  • light: 높이 3m에서 아래를 비추는 조명. 빛의 방향과 중력은 서로 다른 설정입니다.
  • body pos: 공의 기준점을 처음 높이 1m에 둡니다.
  • freejoint: 공이 위치 3방향과 회전 3방향으로 자유롭게 움직일 수 있게 합니다. “힘이 없어도 마음대로 움직인다”는 뜻이 아닙니다.
  • rgba: 빨강·초록·파랑·불투명도. 보이는 색을 정하는 값이며 힘의 크기와는 무관합니다.

관절 없는 body를 만들었다고 자동으로 자유 낙하하지는 않습니다. 부모에 대해 움직일 자유도를 관절로 정의해야 합니다. 바닥은 세계에 고정하고, 공에만 freejoint를 준 이유가 이것입니다.

몸체와 모양을 나누면 무엇이 좋을까?
손잡이와 문판을 한 몸체에 여러 geom으로 붙이면 두 모양이 같은 몸체를 따라 함께 움직입니다. 몸체의 연결 구조와 겉으로 보이는 모양을 따로 관리할 수 있다는 뜻입니다.

설계도와 실험판: MjModel과 MjData

같은 규칙으로 두 판의 보드게임을 하는 상황을 생각해 봅시다. 규칙서는 하나이고, 판 위의 말 위치와 차례는 판마다 따로입니다. MuJoCo에서 규칙서가 MjModel, 지금 판의 상황이 MjData입니다.

MjModelMjData
모양, 질량, 관절 종류, 중력, 시간 간격 등현재 시간, 위치 qpos, 속도 qvel, 계산된 힘·좌표 등
한 설계를 여러 실험이 공유할 수 있음실험마다 별도로 만들 수 있음
모델 = mujoco.MjModel.from_xml_string(xml)
가 = mujoco.MjData(모델)
나 = mujoco.MjData(모델)
mujoco.mj_step(모델, 가)   # 가만 진행한다
mujoco.mj_resetData(모델, 가)  # 가의 상태를 초기화한다

가를 진행해도 나의 시간은 그대로입니다. 같은 모델로 두 실험을 따로 돌릴 수 있다는 것이 이 구조의 요점입니다. 반면 모델.opt.gravity를 바꾸면 이후 그 모델로 계산하는 두 판 모두 새 중력을 씁니다. 상태는 갈라져 있고 규칙은 공유되어 있습니다.

Model을 “바뀌지 않는 설계도”라고 부른 것은 역할을 구분하는 비유입니다. 정말로 수정 불가능한 객체라는 뜻이 아닙니다. 이 페이지에서도 중력을 달의 중력으로 바꿉니다.

예제 출력의 몸체 수 2는 world와 공을 합한 수이고, 모양 수 2는 바닥과 공입니다. freejoint 하나는 qpos 7칸, qvel 6칸을 씁니다. 공 질량 약 4.189kg은 반지름 0.1m 구에 기본 밀도 1000kg/m³를 적용한 값입니다. 숫자가 어디서 나왔는지 이렇게 추적할 수 있어야 질량을 바꿀 때 결과를 예상할 수 있습니다.

교안의 별도 낙하 실험에서 가를 0.5초 진행하면 높이가 −0.231m이고, 나는 1m 그대로입니다. 되감으면 가도 1m로 돌아옵니다. 달 중력(약 1.62m/s²)으로 바꾼 실험의 0.5초 뒤 높이는 0.797m입니다.

여기서 나온 음수 높이를 “공이 바닥을 뚫었다”로 읽지 마십시오. 이 낙하 실험 장면에는 충돌하는 바닥이 없습니다. 앞에서 만든 바닥 포함 장면과는 다른 실험이며, 계산이 위치를 음수까지 그대로 적분한 결과입니다.

resetData는 중력도 지구 중력으로 되돌릴까?
아닙니다. Data의 상태를 초기화할 뿐입니다. Model에서 바꾼 중력 같은 설계 설정까지 원래 XML 값으로 복구하는 함수로 생각하면 안 됩니다.

default · asset · material: 같은 값은 한 번만, 재료는 이름으로

문 한 짝의 <default>는 앞에서 보았습니다. 여기서는 같은 도구 둘을 더 붙입니다. <asset>은 이름을 붙여 둔 재료 창고(무늬 그림인 texture, 그것을 감싼 material)이고, geom은 material="이름"으로 가져다 씁니다.

<default> 안의 class는 “이 아이만 예외” 규칙입니다. 적는 곳과 쓰는 곳이 떨어져 있으니, 쓴 뒤에는 모델에서 읽어 확인합니다.

태그하는 일b06_default_asset.py에서
default (바깥)안 적은 속성의 기본값5~6행: 모든 geom의 마찰 0.8, 색 회색
default class="얼음"이름 붙인 예외 묶음7~9행: 마찰 0.05, 하늘색. 얼음 geom이 class="얼음"으로 고름(18행)
asset의 texture·material이름 붙인 재료 창고11~13행. 바닥 geom이 material="바닥재"로 가져다 씀(16행)
cd C:\code\src\robo\vol3\04-mujoco-basics
..\..\.venv\Scripts\python.exe b06_default_asset.py
바닥: 마찰 0.80, 색 [0.6 0.6 0.6 1. ], 재질 번호 0
나무: 마찰 0.80, 색 [0.6 0.6 0.6 1. ], 재질 번호 -1
얼음: 마찰 0.05, 색 [0.7 0.9 1.  1. ], 재질 번호 -1

읽는 법. ① 나무 geom은 마찰을 한 글자도 안 적었는데 0.80입니다(바깥 default가 물려줌). ② 얼음은 class로 마찰 0.05와 색 [0.7 0.9 1 1]이 바뀌었습니다. 예외는 쓴 곳에만 걸립니다.

③ 재질 번호는 geom.matid입니다. 바닥은 재료 창고의 첫 재질이라 0, 재질을 안 붙인 나무와 얼음은 −1입니다. 마찰은 렌더링이 아니라 접촉 계산에 쓰이는 값이므로, 색이나 무늬를 바꿔도 마찰은 변하지 않습니다.

④ friction의 숫자는 하나가 아니라 셋입니다. 미끄러짐, 비틀림(제자리에서 돌기), 구름에 대한 마찰입니다. 아무것도 적지 않은 geom을 이 컴퓨터에서 읽으면 [1, 0.005, 0.0001]이 나오고, 보통은 첫째 값만 바꿉니다. 두 geom이 닿으면 둘 중 큰 값을 씁니다.

⑤ 실제 로봇 모델은 <asset>에 무늬 말고 3차원 모양 파일(mesh)도 넣습니다. 구글 딥마인드가 공개한 MuJoCo Menagerie라는 모음에 유명한 로봇 팔, 네 발 로봇, 휴머노이드의 MJCF가 이렇게 정리되어 있다고 교과서는 소개합니다(이 수업에서는 열어 보지 않았습니다).

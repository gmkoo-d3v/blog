첨부한 화면의 출력 네 줄 읽기

첫 두 줄은 두 관절을 실제 주어진 속도로 함께 돌리는 계산, 뒤 두 줄은 어깨 하나의 영향만 떼어 확인하는 계산입니다. 네 줄이 모두 같은 속력을 출력한 것이 아닙니다. 아래 숫자는 같은 계산 예의 출력입니다.

화면의 출력이 줄이 알려 주는 것
손끝 속도 [−0.1869, 0.1965]m/s어깨와 팔꿈치의 기여를 더한 순간 속도. 음수 x는 왼쪽, 양수 y는 위쪽입니다.
움직여 잰 속도 [−0.187, 0.1965]m/s0.001초 뒤 FK 위치 차이/시간. 짧은 구간의 평균이라 첫 줄과 미세하게 다릅니다.
첫 열과 손끝 방향의 내적: 0.0어깨만 돌릴 때의 접선 방향과 어깨→손끝 반지름이 직각이라는 확인입니다. 손끝이 멈췄다는 뜻이 아닙니다.
첫 열의 길이 0.6478 / 거리 0.6478어깨 열의 크기(m/rad)와 반지름(m)의 숫자가 같습니다. 어깨만 1rad/s일 때의 속력으로 읽을 수 있으며, 두 모터가 함께 만든 속력 약 0.2712m/s와 다릅니다.

1. 반환값부터: 모터를 하나씩 돌려 본 결과표

위팔 0.4m, 아래팔 0.3m인 팔을 오른쪽으로 쭉 펴세요. 어깨와 팔꿈치 각도는 모두 0rad입니다. 오른쪽이 +x, 위쪽이 +y이고, 반시계 회전이 양수입니다.

q = np.array([0.0, 0.0])
야코비안2(q)
# [[0.0, 0.0],
#  [0.7, 0.3]]
손끝에 생기는 변화첫 열: 어깨만 회전둘째 열: 팔꿈치만 회전
x 방향 영향0 m/rad0 m/rad
y 방향 영향0.7 m/rad0.3 m/rad
  1. 팔꿈치는 고정하고 어깨만 1rad/s: 손끝은 어깨에서 0.7m 떨어져 있습니다. 지금 순간 손끝은 위로 0.7m/s 움직입니다. 첫 열 [0, 0.7]을 읽은 것입니다.
  2. 어깨는 고정하고 팔꿈치만 1rad/s: 손끝은 팔꿈치에서 0.3m 떨어져 있습니다. 지금 순간 위로 0.3m/s 움직입니다. 둘째 열 [0, 0.3]을 읽은 것입니다.
  3. 실제 모터 속도가 다르면: 각 열에 해당 모터 속도를 곱하고 두 기여를 더합니다. 어깨 0.5rad/s, 팔꿈치 −0.2rad/s라면 위쪽 속도는 0.7×0.5 + 0.3×(−0.2) = 0.29m/s입니다.

J 자체는 실제 손끝 속도가 아닙니다. 함수 입력 q에는 현재 각도만 있습니다. 반환한 J는 현재 자세에서의 관절 회전 → 손끝 이동 영향표(m/rad)입니다. 여기에 실제 관절 속도(rad/s)를 곱해야 손끝 속도(m/s)가 됩니다. “각 열이 1rad/s일 때의 속도”라는 설명은 열의 숫자를 읽는 가상 실험입니다.

x 영향이 0이라는 것은 이 순간의 x 속도가 0이라는 뜻입니다. 계속 회전하면 팔이 기울고 x도 변합니다. 1rad/s로 1초 움직인 최종 이동 거리가 [0, 0.7]이라는 뜻도 아닙니다.

그림을 함께 읽기

왼쪽 파란 상자는 관절 속도 두 개, 오른쪽 주황 상자는 손끝의 x·y 속도 두 개입니다. 가운데 네 칸은 두 입력을 두 출력으로 연결하는 계산표 J이며 초록 화살표는 계산 흐름입니다.

팔을 곧게 편 자세를 고정하면 J=[[0,0],[0.7,0.3]] m/rad입니다. 어깨 속도만 1rad/s, 팔꿈치는 0으로 두면 손끝 속도는 (0,0.7)m/s입니다. 첫째 열이 어깨의 기여이기 때문입니다. 아래 코드의 첫 열과 J @ qdot이 바로 이 계산을 합니다.

2. 교안의 실제 함수: 네 칸을 만드는 이유

교안 PDF 19쪽, 교과서 3.5절에 등장하는 함수입니다. 길이와 import는 같은 원본 파일의 정의를 함께 가져왔습니다. 수학의 q₁·q₂를 이 코드에서는 q[0]·q[1]로 저장합니다.

import numpy as np
위팔, 아래팔 = 0.4, 0.3  # m

def 야코비안2(q) -> np.ndarray:
    """2×2 야코비안. 열 i는 '관절 i만 1rad/s로 돌 때의 손끝 속도'."""
    s1, c1 = np.sin(q[0]), np.cos(q[0])
    s12, c12 = np.sin(q[0] + q[1]), np.cos(q[0] + q[1])
    return np.array([[-위팔 * s1 - 아래팔 * s12, -아래팔 * s12],
                     [위팔 * c1 + 아래팔 * c12, 아래팔 * c12]])

먼저 손끝 위치를 만드는 두 막대

위팔 끝까지 간 다음 아래팔 끝까지 갑니다. 길이 L인 막대가 x축에서 θ만큼 기울면 가로 그림자는 L cosθ, 세로 그림자는 L sinθ입니다. 그래서 순기구학의 위치식은 다음 두 줄입니다.

x = 0.4 cos(q[0]) + 0.3 cos(q[0] + q[1])
y = 0.4 sin(q[0]) + 0.3 sin(q[0] + q[1])

왜 아래팔에는 각도를 더하나요? 팔꿈치 각도는 위팔에 비해 얼마나 꺾였는지입니다. 어깨가 30° 돌아가고 팔꿈치가 같은 방향으로 45° 더 꺾이면 아래팔은 고정된 x축에 대해 75°를 향합니다. s12는 sin(30°+45°)입니다. sin30°+sin45°를 계산한 값이 아닙니다.

위치식에서 ‘조금 돌렸을 때 얼마나 바뀌나’만 꺼내기

원의 오른쪽 끝에서 반시계로 출발하면 위로 갑니다. 원 위의 다른 점에서도 이동 방향은 반지름과 직각입니다. 반지름 방향 [cosθ, sinθ]를 반시계로 90° 돌리면 [−sinθ, cosθ]가 됩니다. 이것이 cos가 −sin으로, sin이 cos로 바뀌는 물리적 이유입니다. 미분은 이 순간 변화 비율을 계산합니다.

반환 배열의 칸코드그 항이 필요한 이유
첫 행·첫 열: 어깨→x-위팔*s1 - 아래팔*s12어깨를 돌리면 위팔도, 그 위에 달린 아래팔도 함께 방향을 바꿉니다. 두 막대의 x 변화 기여를 더합니다.
둘째 행·첫 열: 어깨→y위팔*c1 + 아래팔*c12같은 두 막대의 y 변화 기여입니다. 위팔과 아래팔 모두 들어갑니다.
첫 행·둘째 열: 팔꿈치→x-아래팔*s12어깨 각도를 고정한 채 팔꿈치만 돌리면 위팔은 그대로입니다. 아래팔의 x 변화만 남습니다.
둘째 행·둘째 열: 팔꿈치→y아래팔*c12아래팔의 y 변화만 남습니다.

앞의 마이너스는 “모터를 항상 반대로 돌려라”라는 명령이 아닙니다. 위치가 회전에 따라 변하는 방향을 나타냅니다. 사인 값도 자세에 따라 음수가 될 수 있으므로 실제 부호는 현재 q로 계산해야 합니다. q[0]+q[1]은 어느 관절 각도를 0.01rad 늘려도 0.01rad 늘어나므로 여기서는 추가 배율이 1입니다.

문법이 잠깐 헷갈릴 때만: 함수·배열·반환

def는 계산 방법을 정의합니다. 야코비안2(q)로 호출할 때 계산합니다. -> np.ndarray는 반환 형태에 대한 힌트이며 값을 배열로 변환하는 명령이 아닙니다. 실제 배열은 np.array(...)가 만듭니다.

s1, c1 = ...은 두 계산 결과를 각각 이름에 저장합니다. 반환문의 바깥 목록 안에는 행 두 개가 있습니다. 첫 목록이 x 행, 다음 목록이 y 행입니다. return은 그 2×2 배열을 호출한 쪽으로 돌려줍니다. 이 함수 안에는 모터를 움직이는 명령이 없습니다.

3. 실제 예제의 30°·45°를 함수에 넣어 추적하기

교안의 속도 예제 b13_velocity.py는 다음 입력을 씁니다. NumPy 삼각함수는 라디안을 받습니다.

q = np.deg2rad([30.0, 45.0])
관절_속도 = np.array([0.5, -0.2])
손끝_속도 = 야코비안2(q) @ 관절_속도

q[1]0.785398rad = 45°위팔에 대한 팔꿈치 각도

s1, c10.500000, 0.866025위팔 방향의 세로·가로 비율

첫 열을 말로 읽어 보세요. “현재 자세에서 어깨만 양의 방향으로 1rad/s 돌리면 손끝은 왼쪽으로 약 0.4898m/s, 위로 약 0.4241m/s 움직인다.” 둘째 열은 팔꿈치만 돌리는 같은 실험입니다. 반환값을 이렇게 읽을 수 있으면 함수의 역할을 이해한 것입니다.

4. @는 두 모터의 영향을 합치는 계산

실제로 어깨는 +0.5rad/s, 팔꿈치는 −0.2rad/s로 돌립니다. 각 열이 알려 주는 ‘단위 회전당 영향’에 실제 속도를 곱합니다.

손끝 방향어깨 기여: 첫 열 × 0.5팔꿈치 기여: 둘째 열 × (−0.2)두 기여의 합
x−0.244889m/s+0.057956m/s−0.186933m/s
y+0.212028m/s−0.015529m/s+0.196499m/s

팔꿈치는 음의 속도로 돌기 때문에 둘째 열의 기여 방향이 뒤집힙니다. 어깨가 만드는 왼쪽·위쪽 이동을 일부 상쇄합니다. 최종 손끝은 왼쪽으로 약 0.187m/s, 위로 약 0.1965m/s입니다. 두 모터의 각속도를 먼저 더하는 것이 아니라, 각 모터의 손끝에 대한 영향을 더합니다.

야코비안2(q).shape   # (2, 2): 손끝 성분 2 × 관절 2
관절_속도.shape      # (2,): 관절 속도 두 개
손끝_속도.shape      # (2,): x 속도, y 속도
# 손끝_속도 ≈ [-0.186933, 0.196499]

@는 각 행에서 곱한 결과들을 더합니다. *를 쓰면 NumPy가 열별로 속도를 곱한 2×2 기여표만 남고 합산하지 않습니다. 따라서 이 예제의 손끝 속도 결과가 아닙니다. NumPy의 (2,) 배열은 수학에서 열벡터처럼 사용하는 1차원 배열이며, 실제 shape가 (2,1)인 2차원 열 배열과는 구분합니다.

5. 다음 세 줄은 왜 순기구학을 다시 호출할까?

간격 = 0.001
움직인_거리 = 순기구학2(q + 관절_속도 * 간격) - 순기구학2(q)
print("실제로 움직여 잰 속도   :", 깔끔(움직인_거리 / 간격, 4), "m/s")

야코비안의 결과가 납득되는지, 아주 짧게 지난 뒤의 위치 차이로 비교합니다. 원본의 “실제로 움직여”는 이 코드에서는 순기구학으로 전후 위치를 계산한다는 뜻입니다. 하드웨어를 움직이거나 물리 시뮬레이터를 실행하는 코드는 아닙니다.

  1. 관절_속도 * 간격: rad/s × s = rad. 0.001초 동안 어깨는 +0.0005rad, 팔꿈치는 −0.0002rad 바뀝니다.
  2. q + ...: 새 각도는 [0.524099, 0.785198]rad입니다. 각도에 속도를 그대로 더하지 않고, 시간을 곱한 각도 변화량을 더합니다.
  3. 순기구학2(새 q): 새 손끝 위치는 약 [0.423868895, 0.489974209]m입니다. 현재 위치는 [0.424055875, 0.489777748]m입니다.
  4. 새 위치 − 현재 위치 = [−0.000186980, +0.000196461]m. 이를 0.001s로 나누면 [−0.186980, +0.196461]m/s입니다.

J로 얻은 [−0.186933, +0.196499]와 매우 가깝지만 똑같지는 않습니다. J는 시작 순간의 속도, 위치 차이/시간은 짧은 구간의 평균 속도입니다. 그동안 자세도 조금 달라집니다. 큰 시간 간격까지 한 번 구한 J로 정확하게 예측할 수는 없습니다.

마지막 ‘첫 열의 내적·길이’ 출력은 무슨 확인인가?
첫_열, 손끝 = 야코비안2(q)[:, 0], 순기구학2(q)
첫_열 @ 손끝
np.linalg.norm(첫_열)
np.linalg.norm(손끝)

[:, 0]은 모든 행에서 첫 번째 열을 꺼냅니다. 이 평면 예제에서는 어깨가 원점이므로 손끝 위치 벡터가 어깨→손끝 반지름입니다. 어깨만 회전할 때 손끝 속도는 반지름과 수직이어서 두 벡터의 내적이 0입니다.

숫자로는 손끝 p≈[0.424056, 0.489778], 첫 열≈[−0.489778, 0.424056]입니다. 즉 첫 열은 [−py, px]이므로 내적은 −pypx+pxpy=0입니다. 첫 열과 p 모두 0이 아닌데도 서로 직각이면 내적은 0입니다.

이번 자세에서 손끝까지 거리는 약 0.647847m이고, 첫 열의 크기는 약 0.647847m/rad입니다. 1rad/s를 곱하면 속력은 약 0.647847m/s입니다. 문 경첩에서 멀수록 같은 각속도에 더 빨리 움직인다는 v=ωr의 확인입니다. 숫자가 같아도 거리와 J 열의 단위는 다릅니다. 두 모터의 실제 속도를 반영한 np.linalg.norm(손끝_속도)는 약 0.271212m/s입니다. 원본 마지막 줄은 이 값을 출력하지 않습니다.

6. 익숙해진 뒤 스스로 확인하기

아래 답을 먼저 읽어도 됩니다. ‘현재 자세를 바꿨는가, 모터 속도를 바꿨는가’를 함께 구분해 봅시다.

① 같은 자세에서 관절 속도를 [1.0, −0.4]로 두 배 만들면 J와 손끝 속도는?

J는 같습니다. J의 입력 q를 바꾸지 않았기 때문입니다. 손끝 속도만 두 배가 되어 약 [−0.373867, +0.392998]m/s가 됩니다. “모터가 빨라졌으니 J의 숫자도 두 배”라고 생각하면 자세 영향표와 실제 속도를 혼동한 것입니다.

② 모터를 모두 멈추면, J의 숫자도 전부 0일까?

아닙니다. 같은 q의 J는 그대로지만, [0,0]rad/s를 곱한 손끝 속도가 [0,0]m/s입니다. J는 ‘움직인다면 어떤 영향이 생길까’를 기록합니다. 실제로 움직이고 있다는 선언이 아닙니다.

③ 팔을 다시 쭉 펴고 같은 [0.5, −0.2]rad/s로 돌리면?

자세 q가 달라졌으므로 J를 다시 계산합니다. J=[[0,0],[0.7,0.3]]이고 손끝 속도는 [0,0.29]m/s입니다. 30°·45°일 때의 J를 그대로 쓰면 왼쪽 속도를 잘못 예측합니다. J(q)의 괄호 q는 이 의존성을 알려 줍니다.

7. 이제 직접 실행해 한 숫자만 바꾸기

여기까지는 읽기였습니다. 같은 계산을 직접 돌려 보려면 practice/jacobian_followalong.py와 따라하기 안내를 쓰면 됩니다. 스크립트는 교안의 순기구학2·야코비안2와 b13_velocity.py의 계산을 NumPy만으로 한 파일에 옮긴 사본이며, 링크 길이는 0.4 m·0.3 m로 고정되어 있습니다. 숫자만 계산하고 실제 로봇을 움직이지 않습니다.

로보틱스 학습 폴더에서 PowerShell을 열고 아래 명령을 실행하면 기본값(30°·45°, 0.5·−0.2 rad/s)으로 실행됩니다.

python practice\jacobian_followalong.py
  1. 기본값 실행: J 네 칸, 열별 기여, v, 속력, 유한차분 평균이 한 번에 출력됩니다. 이 값이 기준입니다.
  2. --dq 0.5 0: 각도는 그대로 두고 팔꿈치만 멈춥니다. J는 그대로인데 둘째 열 기여만 0이 되는 것을 봅니다.
  3. --q 0 0: 속도는 그대로 두고 자세만 폅니다. J가 [[0, 0], [0.7, 0.3]]로 다시 계산되는 것을 봅니다.

세 번 실행하면 확인되는 것: J는 자세 q의 함수이고, qdot은 J에 곱해질 때만 속도가 됩니다. 세 실행의 실제 출력과 해설은 practice/README.md에 정리해 두었습니다. 그다음 파일 위쪽의 Q_DEG_DEFAULT 한 숫자만 바꿔 다시 실행해 보세요.

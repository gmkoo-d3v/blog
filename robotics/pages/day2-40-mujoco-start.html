MuJoCo 시작하기: 확인, 뷰어, 숫자로 보기

시범 보기 → 따라 하기 → 이유 이해 → 선택적 확인

3장에서는 팔을 숫자로만 계산했습니다. 이제 그 팔을 컴퓨터 속 실험실에 넣고 시간이 흐르게 합니다. 이 장의 끝 그림은 팔이 상자를 탁자 밖으로 미는 장면입니다. 그 전에 할 일은 세 가지입니다. MuJoCo가 켜지는지 확인하고, 뷰어 창을 읽고, 내 코드를 돌리는 길을 아는 것입니다.

코드 블록을 내 컴퓨터에서 돌리는 방법은 예제 실행하기에 있습니다.

MuJoCo 2일차 교안(49쪽) 13차시 앞부분(p.1–9)을 풀어 쓴 글입니다. 교안 쪽 번호로 찾으려면 MuJoCo 교안 쪽에서 찾기를 쓰세요.

여섯 부품을 순서대로 모읍니다

완성 장면은 부품 여섯 개로 이루어집니다. 한 번에 한 부품씩 붙이고, 붙일 때마다 숫자나 그림으로 확인합니다.

교안 차시새로 붙이는 부품이 노트에서
13장면: 탁자, 팔, 상자를 글(XML)로 적기이 글 → XML 읽는 법 → 문 한 짝으로 읽는 태그
14시간: mj_step으로 0.002초씩 흘리기Model과 Data, 상태의 칸
15사진과 채점: 화면에 찍고 공식과 비교낙하와 마찰로 채점
16모터: 관절에 목표 각도 주기위치 읽기와 모터
17센서와 접촉: 느낀 값과 닿은 곳 읽기센서, 충돌, 안정성
18조립: 부품을 합쳐 상자 밀기두 관절 팔로 상자 밀기

한 차시는 50분입니다. 도입 5분, 설명과 시연 30분, 직접 실행 10분, 정리 5분으로 나뉩니다. 13~15차시는 장면과 시간, 16~18차시는 부품과 조립입니다. 예제 하나는 1초 안쪽으로 끝나게 만들어져 있습니다. 직접 재 보니 b01, b02, b05가 파이썬을 켜는 시간까지 합쳐 0.34~0.40초였습니다.

이 글과 다음 글(13차시)을 마치면 할 수 있어야 하는 것
  1. MuJoCo가 무엇이고 왜 쓰는지 말할 수 있다.
  2. 로봇 부품(링크·관절·모터·센서)을 MJCF 태그와 짝지을 수 있다.
  3. XML 문법으로 공 하나가 있는 장면을 적고, 모양의 크기와 질량을 읽을 수 있다.

13차시에 쓰는 예제는 v01_viewer_pendulum.py, b01_hello.py, b02_first_scene.py, b05_geom_mass.py입니다.

1. 켜지는지 확인하기

첫 목표는 한 줄입니다. 버전 숫자가 나오면 MuJoCo가 설치되어 있습니다. 이 컴퓨터의 예제 환경은 C:\code\src\robo 폴더의 .venv입니다.

C:\code\src\robo\.venv\Scripts\python.exe -c "import mujoco; print(mujoco.__version__)"

이 컴퓨터에서 나온 출력은 3.17.0이었습니다. 같은 폴더의 .venv 파이썬은 3.12.3입니다.

그냥 python은 다른 파이썬입니다

같은 3.12.3인데도 명령 앞의 경로를 빼고 python -c "import mujoco"만 치면 이 컴퓨터에서는 ModuleNotFoundError: No module named 'mujoco'가 나왔습니다.

PATH에 걸린 파이썬(...\Programs\Python\Python312)에는 MuJoCo가 없고, MuJoCo는 .venv 안 파이썬에만 있기 때문입니다. 예제를 돌릴 때는 .venv\Scripts\python.exe를 쓰세요. 자세한 방법은 내 PC에서 예제 실행하기에 모았습니다.

명령·함수하는 일언제 쓰나
pip install mujoco라이브러리를 내려받아 설치처음 한 번
import mujoco파이썬에서 불러오기모든 예제의 첫 줄
mujoco.__version__설치된 버전 보기설치 확인
다른 컴퓨터에 처음 설치한다면, 그리고 자주 막히는 곳

방법은 둘입니다. 어느 쪽이든 마지막에 버전 숫자가 나오면 성공입니다.

python -m venv .venv
.venv\Scripts\activate
pip install mujoco numpy scipy matplotlib pillow
python -c "import mujoco; print(mujoco.__version__)"

두 번째 방법은 예제 폴더의 pyproject.toml을 읽어 같은 버전으로 맞추는 uv sync입니다. 이 컴퓨터에는 환경이 이미 있어서 위 설치 명령은 직접 실행하지 않았습니다. 확인한 것은 두 가지입니다.

MuJoCo 패키지가 요구하는 파이썬은 3.10 이상이고, 이 예제 프로젝트는 파이썬 3.12.x와 mujoco==3.17.0으로 고정되어 있습니다. 교안은 파이썬 3.10 이상, 3.11~3.13을 권합니다.

  • 예제 폴더 밖에서 돌려 ModuleNotFoundError가 날 때: 도우미 파일(팔장면.py, 그림도구.py)은 04 폴더 안에 있습니다. 쓰는 방법은 예제 실행하기에 있습니다.
  • 그래프의 한글이 □로 깨질 때: 글꼴을 Malgun Gothic으로 바꿉니다. 이 컴퓨터의 matplotlib은 Malgun Gothic을 찾아 목록에 가지고 있었습니다. 예제의 그림도구.py는 5행에서 D2Coding을 지정합니다. 이 컴퓨터에는 그 글꼴이 있어서 b12_frames.py가 경고 없이 돌았습니다. 글꼴이 없는 컴퓨터에서는 findfont: Font family '…' not found. 꼴의 경고가 나오고 한글이 □가 됩니다(이 컴퓨터에 없는 글꼴 AppleGothic을 지정해 보니 그 경고와 □가 나왔습니다). 내 코드에서는 plt.rcParams["font.family"] = "Malgun Gothic" 한 줄을 그림 그리기 전에 넣으면 됩니다(윈도 글꼴이며, 이 한 줄로 한글 제목을 그려 경고 없이 저장되는 것을 확인했습니다).
  • 맥에서 창을 코드로 열 때: launch_passive는 python 대신 MuJoCo와 함께 설치되는 mjpython으로 실행해야 합니다. 그냥 돌리면 RuntimeError: `launch_passive` requires that the Python script be run under `mjpython` on macOS라는 오류가 나옵니다(교과서 부록의 실행 기록이며 이 컴퓨터는 윈도라 확인하지 않았습니다). 윈도와 리눅스는 평소처럼 python입니다.
  • 화면이 없는 서버에서 사진을 찍을 때: 환경 변수 MUJOCO_GL을 egl 또는 osmesa로 정합니다(교과서 부록의 안내이며 확인하지 못했습니다). 숫자만 계산할 때는 필요 없습니다.

MuJoCo는 무엇이고, 왜 쓸까

물리 엔진입니다. 중력, 관절, 부딪힘을 계산해서 “0.002초 뒤에는 어디에 있을까”를 계속 구해 주는 프로그램입니다. 이름은 Multi-Joint dynamics with Contact의 줄임말로, 관절이 여럿 달리고 서로 부딪히는 물체를 다루는 데 쓰인다는 뜻입니다.

로봇 연구와 강화학습에서 널리 쓰입니다. 교안과 교과서에 따르면 2012년에 Emo Todorov가 만들었고, 2021년 Google DeepMind가 무료 오픈 소스(Apache 2.0)로 공개했습니다. 실제 로봇 앞에서 하기 어려운 다섯 가지를 해 줍니다.

  • 부서지지 않습니다. 팔이 탁자를 쳐도 다시 시작하면 그만입니다.
  • 같은 입력이면 같은 결과입니다. 진자를 두 번 따로 돌려 500걸음 뒤 각도를 비교했더니 소수 끝자리까지 똑같았습니다.
  • 값이 다 보입니다. 각도, 속도, 닿은 곳을 숫자로 읽을 수 있습니다.
  • 빠릅니다. 교안은 실제 시간보다 수백 배 빨리 돌릴 수 있다고 설명합니다(그 배수는 내가 재지 않았습니다).
  • 수만 번 반복할 수 있습니다. 사람이 눈으로 볼 수 없는 횟수도 됩니다(뒤 장의 학습하는 로봇이 이 성질을 씁니다).
  • 화면 없이도 돌립니다. 숫자만 필요하면 창을 열지 않아도 됩니다. 아래에서 두 방식을 비교합니다.

2. 뷰어로 진자 하나 보기

숫자로 보기 전에 먼저 눈으로 봅니다. 진자 하나를 창에 띄우는 예제 파일이 있습니다.

cd C:\code\src\robo\vol3\04-mujoco-basics
..\..\.venv\Scripts\python.exe v01_viewer_pendulum.py

창이 열리면 제목이 MuJoCo : 진자입니다. 제목에 쓰이는 이름은 XML 맨 위 <mujoco model="진자">에 적은 모델 이름입니다. 같은 파일에 --arm을 붙이면 제목이 MuJoCo : 평면 2관절 팔인 창이 열립니다.

가운데 장면부터 보세요

  1. 가운데에서 붉은 공을 찾습니다. 공이 매달린 막대 끝에서 좌우로 흔들립니다. 막대 윗부분은 화면 위로 이어져 있습니다. 공 아래 회색 타원은 바닥에 비친 그림자입니다.
  2. 왼쪽 패널은 도구함입니다. File에는 저장·종료·화면 저장 버튼이, Option에는 보기 옵션과 Help 버튼이, Simulation에는 정지·재시작 버튼이 있습니다.
  3. 오른쪽 패널은 처음에 접혀 있습니다. Control을 펼치니 Clear all 버튼 하나만 보였습니다. 진자에는 모터가 없어서 조절할 칸이 없기 때문입니다. 모터가 있는 팔 장면에서는 모터마다 칸이 생기는지 여기서는 확인하지 않았습니다.

표에는 Space가 재생/정지로 적혀 있습니다. 그런데 이 예제는 launch_passive로 열어서 내 반복문이 시간을 흘립니다. 그 창에서는 Simulation 패널의 Pause/Run이 회색으로 눌리지 않았고, 창에 Space를 보내도 시뮬레이션 시간은 계속 올랐습니다.

공식 설명서도 이 방식에서는 재생·정지와 한 걸음씩 가기 단축키가 듣지 않는다고 적습니다. 멈추고 싶으면 반복문 안에서 멈추게 짜거나, 아래의 일반 뷰어를 쓰세요.

뷰어를 켜는 코드는 세 줄입니다
import mujoco.viewer

with mujoco.viewer.launch_passive(model, data) as viewer:
    while viewer.is_running():       # 창이 열려 있는 동안
        mujoco.mj_step(model, data)  # 0.002초 진행
        viewer.sync()                # 바뀐 상태를 창에 보냄

launch_passive는 창만 띄우고 곧바로 돌려줍니다. 시간을 얼마나 흘릴지는 내 반복문이 정합니다. viewer.sync()를 불러야 창에 새 상태가 반영된다고 공식 설명서에 적혀 있습니다. 예제 파일은 여기에 걸음마다 짧게 쉬는 줄을 더해서 창 속 시간이 실제 시간과 비슷하게 가도록 맞춥니다. 창을 닫으면 is_running()이 거짓이 되어 반복문이 끝납니다.

멈추기와 한 걸음씩 가기까지 쓰고 싶다면 코드를 건네지 않고 창만 여는 mujoco.viewer.launch(model, data)나 python -m mujoco.viewer가 있습니다. 이쪽은 창이 시간을 흘리는 방식이고, 이 컴퓨터에서 키를 눌러 확인하지는 않았습니다.

같은 진자를 숫자로 보기

창을 열지 않아도 같은 진자를 계산할 수 있습니다. 천장에 매단 0.5 m 진자를 옆으로 90° 들었다 놓고, 0.2초마다 각도를 읽은 결과입니다(b01_hello.py를 .venv 파이썬으로 실행).

시간(초)0.00.20.40.60.81.0
각도(°)90.067.56.6−58.7−89.2−75.3

빨간 점에서 막대를 따라 공까지 보세요

  1. 빨간 점이 경첩(회전 중심)입니다. 진자는 이 점에 매달려 돕니다. 0°에서는 공이 바로 아래(회색 원)에 있습니다.
  2. 주황 공이 처음 자리(90°)입니다. 놓으면 하늘색 공 자리를 지나 회색 원 쪽으로 내려옵니다. 0.2초 뒤에는 67.5°이고 공은 (−0.4619, 0.8087)에 있습니다.
  3. 회전 축은 화면을 뚫고 들어가는 y축입니다. 그래서 공은 x–z 면 안에서만 움직입니다.
xml = """<mujoco><worldbody>
  <body pos="0 0 1">                                  <!-- ① 회전 중심: 높이 1 m -->
    <joint type="hinge" axis="0 1 0"/>                  <!-- ② 도는 축: y -->
    <geom type="sphere" pos="0 0 -0.5" size="0.05"/>    <!-- ③ 공: 중심에서 0.5 m 아래 -->
  </body></worldbody></mujoco>"""
모델 = mujoco.MjModel.from_xml_string(xml)
데이터 = mujoco.MjData(모델)
데이터.qpos[0] = np.deg2rad(90)        # ④ 처음 각도 90°
for _ in range(100):
    mujoco.mj_step(모델, 데이터)       # ⑤ 한 걸음 0.002초 x 100 = 0.2초

이 코드가 b01_hello.py의 핵심입니다. 한 가지 더 확인했습니다. 100걸음 직후 데이터.geom_xpos를 읽으면 공 위치가 (−0.4634, 0.8122)로 한 걸음 이전 값이었고, mujoco.mj_forward(모델, 데이터)를 한 번 부른 뒤에 읽어야 위 그림의 (−0.4619, 0.8087)이 나왔습니다.

각도(qpos)는 이미 새 값이지만 위치(xpos)는 따로 한 번 더 계산해야 하기 때문입니다.

창에서 본 흔들림과 이어서 읽으세요. 0.4초 근처에서는 거의 수직(6.6°)으로 가장 빠르게 지나가고, 0.8초에는 반대편 끝(−89.2°)까지 올라갑니다. 숫자 여섯 개만으로도 진자가 한쪽 끝에서 반대쪽 끝으로 넘어가는 모습이 보입니다.

뷰어(창)스크립트(숫자·파일)
얻는 것눈으로 본 움직임출력한 숫자, 저장한 그림 파일
정답과 비교눈대중공식과 바로 빼서 비교

내가 쓴 XML을 창에 띄우기: XML을 box.xml로 저장하고 아래처럼 열면 됩니다. 이 컴퓨터에서 model="box"인 파일을 열었더니 제목이 MuJoCo : box인 창이 떴습니다. 옵션 없이 python -m mujoco.viewer만 치면 제목이 MuJoCo인 빈 창이 열리고, 공식 설명서는 여기에 파일을 끌어다 놓으라고 안내합니다.

C:\code\src\robo\.venv\Scripts\python.exe -m mujoco.viewer --mjcf=box.xml

예제의 팔 장면도 같은 방법으로 열 수 있습니다. 04 폴더의 팔장면.py 안에 XML이라는 글자 덩어리가 있습니다. 이것을 파일로 저장하면 됩니다.

open("arm.xml", "w", encoding="utf-8").write(XML)   # from 팔장면 import XML 을 한 뒤에

이 컴퓨터에서 arm.xml을 위 명령으로 열었더니 제목이 MuJoCo : 평면 2관절 팔인 창이 떴습니다. 파일 이름을 한글(팔장면.xml)로 저장했을 때는 파일을 읽지 못하고 제목이 그냥 MuJoCo인 빈 창이 열렸으니, XML 파일 이름은 영어로 지으세요. 교안도 같은 방식(파일로 저장한 뒤 빈 창에 끌어다 놓기)을 안내합니다.
